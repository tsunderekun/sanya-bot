# Техническое задание: Расширение функционала бота «Саня Пониёб»

## 1. Контекст и архитектура
Бот работает на модульной архитектуре `sanya/` (aiogram 3.x, SQLite с выделенным воркером в `sanya/database.py`, локальная Ollama с моделью `sanya:latest`, vision-модель `moondream:latest`).
Все изменения должны следовать установленным стандартам: асинхронность, изоляция SQLite-операций через репозиторий, сохранение обратной совместимости и прохождение существующего набора тестов `tests/`.

---

## 2. Новые задачи и спецификация требований

### Задача 1. Канальные мемы и видео по команде `/мем` (универсальный сборщик + МДМ)
1. **Слушатель постов из каналов:**
   - Добавить роутер для сообщений из каналов (`@router.channel_post()`).
   - Если бота добавили в любой канал (например, канал «МДМ» `https://t.me/mestodm` или любой другой донорский канал), бот автоматически перехватывает посты с медиа (фото, видео, анимации/GIF).
   - Сохранять в SQLite таблицу `channel_memes`: `id`, `channel_id`, `message_id`, `media_type` ('photo', 'video', 'animation'), `file_id`, `file_unique_id`, `created_at`.
   - Использовать `file_id` напрямую: это исключает скачивание гигабайт видео на диск сервера и делает отправку мгновенной.
2. **Команда `/мем` (и `/meme`):**
   - Выбирает случайную запись из таблицы `channel_memes` и отправляет в чат строго **без подписи и текста оригинала** (`send_photo`, `send_video`, `send_animation`).
3. **Фоллбэк:**
   - Если база постов пуста (бота ещё не успели добавить в канал), бот делает лёгкий скрейпинг последних медиа через веб-превью `https://t.me/s/mestodm` и отправляет файл.

### Задача 2. Рандомные картинки по триггеру на «хорс» (`sloiper.zip`)
1. **Архив с артами:**
   - Локальный путь к архиву на машине разработчика: `C:\Users\atsun\Downloads\Telegram Desktop\sloiper.zip` (~1 ГБ, 797 файлов `.png`).
   - На сервере архив распаковывается в директорию `data/sloiper/` (добавить путь в `sanya/config.py`: `SLOIPER_DIR`).
2. **Триггер:**
   - Слово «хорс» и его формы (`\b(?:хорс[а-я]*|horse[a-z]*)\b`).
3. **Антиспам и логика отправки:**
   - Срабатывание с вероятностью ~40% либо с кулдауном 2–3 минуты на чат, чтобы не превращать переписку во флуд.
   - Отправка случайного файла из папки через `types.FSInputFile` методом `send_photo` (чтобы сразу отображалось превью картинки).

### Задача 3. Экспертный интерес Сани к нейросетям (10% случаев)
1. **Ключевые слова в сообщениях:**
   - `SD`, `Stable Diffusion`, `ComfyUI`, `Automatic1111`, `LoRA`, `чекпоинт`, `сэмплер`, `ddim`, `euler`, `cfg`, `апскейл`, `ControlNet`, `промпт`, `ollama`, `оллама`, `кванты`, `gguf`, `инференс`, `vllm`.
2. **Логика поведения:**
   - При обнаружении этих тем бросается вероятность (10%).
   - При выпадении 10%: в системный контекст подмешивается скрытая инструкция (`Mode.CHAT` / `Mode.DETAIL`): Саня искренне заинтересован темой нейросетей, врубает эксперта-брони по генерации артов и оптимизации моделей (советует ноды ComfyUI, сэмплеры типа DPM++ 2M Karras, чекпоинты Pony XL / AutismMix, квантование Q4_K_M для слабых карт, спрашивает про граф нод или рабочий промпт).
   - В остальных 90% случаев — обычный перекупский сарказм или бытовой ответ.

---

### Задача 4. Продвинутый поиск по боорам / r34 без дубликатов
1. **Защита от дублей:**
   - Создать таблицу `booru_history (chat_id, image_id, created_at)`.
   - Хранить последние 200 выданных ID картинок на каждый чат. При запросе исключать уже отправленные ID.
   - Использовать случайный сдвиг (random page / offset) при обращении к API Derpibooru / Rule34, чтобы не отдавать всегда первые 3 арта.
2. **Обработка запросов с одним тегом и подсказки:**
   - Если пользователь пишет только один тег (например `/booru fluttershy`):
     - Автоматически подмешивать теги базового качества (`score.gt:25`, `safe` по умолчанию, если не указано иное).
     - Добавлять в ответ или отдельной репликой пацанскую подсказку от Сани:
       *«Слышь, тегов накинь нормально через запятую (например solo, cute, safe), а то один тег вбил и ждёшь шедевр клоун»*.
3. **Мульти-источники:**
   - Derpibooru (для поняш) + Rule34 / Gelbooru API (для аниме и игровых персонажей).

---

### Задача 5. OCR текста на картинках и скриншотах
1. **Интеграция OCR:**
   - Добавить извлечение печатного текста с присылаемых фото/скриншотов (кириллица + латиница) через быстрый локальный движок (например `rapidocr_onnxruntime` или `pytesseract`).
2. **Связка с LLM:**
   - Распознанный текст передаётся в контекст Сани вместе с общим описанием от `moondream`:
     *«Текст на скриншоте/фото: <распознанный текст>»*.
   - Саня сможет точно читать ошибки синих экранов (BSOD), логи консоли, переписки в мессенджерах и ценники на Авито.

---

### Задача 6. Команды `/железо` и `/оцени`
1. **Команда `/железо` (или `/сетап`):**
   - Выводит информацию о железе пользователя, которую Саня тихо подслушал через систему `sanya/observations.py`. Если ничего не знает — отшучивается в стиле: *«Ты мне ещё не хвастался своим хламом, напиши чё у тебя за видяха или проц»*. При указании кента (`/железо витек`) — выдает его подтвержденный конфиг из `lore.py`.
2. **Команда `/оцени <название железки>` (или `/барыга`):**
   - Саня выдает моментальную оценку девайса в перекупском стиле: реальная вилка цен по низу Авито, за что скинуть цену («после майнинга / без коробки») и за сколько быстро слить «до порога».

## 3. Критерии приёмки
1. Написать модульные тесты в папке `tests/` на каждую новую функцию.
2. Код должен успешно проходить `python -m unittest discover -s tests -v` и `ruff check`.
3. Составить краткий handoff-файл с описанием внесенных изменений и инструкцией по обновлению БД.
