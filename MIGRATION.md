# Переход на модульную версию

Точка входа не изменилась: `python bot.py`. Копировать нужно и `bot.py`, и весь пакет `sanya/`. Бот не меняет установленную модель Ollama.

| Модуль | Ответственность |
| --- | --- |
| `config.py`, `prompts.py`, `lore.py` | Настройки, голос Сани, база персонажей и стикерпаков |
| `database.py`, `schema.py`, `repository.py` | SQLite: один выделенный поток и одно WAL-соединение, совместимая схема и запросы |
| `memory.py`, `llm.py`, `intent.py` | Бюджет контекста, Ollama, изоляция thinking, режим ответа |
| `services/`, `handlers/`, `main.py` | FIFO-очередь, поиск/медиа/доставка, роутеры, управление ресурсами |

## Перед переключением

1. Проверь `DB_PATH` и останови старый экземпляр. Сними резервную копию через SQLite Backup API (учитывает WAL; не копируй только файл `.db` у работающего процесса). Например, из каталога с БД, указав фактический путь:

   ```bash
   python -c "import sqlite3; s=sqlite3.connect('file:sanya_memory.db?mode=ro',uri=True); d=sqlite3.connect('sanya-pre-refactor.db'); s.backup(d); print(d.execute('PRAGMA integrity_check').fetchone()[0]); d.close(); s.close()"
   ```

   Используй новое имя для каждой копии. Для проверки запуска сделай отдельную рабочую копию бэкапа и укажи её в `DB_PATH` вместе с токеном тестового бота.
2. Установи `python -m pip install -r requirements.txt`. Оставь текущий `.env`, сверив параметры с `.env.example`. Запусти:

   ```bash
   python -m compileall -q bot.py sanya tests
   python -m unittest discover -s tests -v
   python bot.py
   ```
3. На тестовом боте проверь обычный бёрст, русский и англоязычный запросы на код, SD-промпт, `/search`, `/pic`, фото для `moondream`, а также `/delkent`, `/delchat`, `/delfact` с несколькими ID. DDL использует реальные имена из старого `bot.py`: `kent_facts_entries` и `auto_observed_facts`. Существующие строки не переименовываются и не пересоздаются. Лимит окна не удаляет историю из файла.
4. Сверь `ollama show sanya:latest --modelfile` с серверной моделью. `Modelfile` в репозитории ссылается на 12B и безусловно открывает канал thought; **не пересоздавай** из него рабочую E4B. На тестовой модели проверь `think: true` и `think: false` отдельно. В журнале сравни `prompt_eval_count` на одних и тех же репликах, включая длинный кириллический текст и код. Окно истории ограничено 14 000 символами; 8 500 — целевой бюджет оценки полного запроса, не точный подсчёт токенизатором Gemma. Если модель его превышает, бот пишет предупреждение; для строгого лимита нужен счётчик с точным серверным шаблоном и токенизатором.
5. После проверки останови тестовый процесс, укажи продовый `DB_PATH` и запусти один экземпляр с продовым токеном. Для отката останови новый процесс и верни старый код. Если нужно восстановить исходное состояние БД, сначала отдельно сохрани новую БД с изменениями после переключения. Восстанавливай бэкап в новый файл и переключай `DB_PATH`, чтобы не смешивать его со старыми `-wal`/`-shm`.

Поиск автоматически подключается при явной просьбе или при неуверенном ответе на фактический вопрос; отдельный LLM-классификатор больше не запускается на каждой реплике. Код и промпты не включают этот веб-поиск. `LOG_OLLAMA_THINKING=true` включает отдельный DEBUG-лог скрытого текста. Не включай его в общедоступном журнале: мысли могут повторять приватные фрагменты переписки.
